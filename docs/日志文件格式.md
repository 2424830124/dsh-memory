# 日志文件的格式

日志是**按天自动建**的：某一天第一次往里写东西时插件建出那一天的文件，不需要（也不应该）手工新建。所以这里记的是「落盘长什么样」，不是「复制这份开始写」。

`file_name` 就是日期，写成 `YYYY-MM-DD`。

## 整体形状

```yaml
meta_data:
  file_name: <yyyy-mm-dd>
  desc: <desc>

data:
  <yyyy-mm-dd>:
    <hh:mm> <summary>:
      keyword: []
      update_at: <time>
      desc: <detail>
```

## `meta_data` 只能写两项

`file_name` 和 `desc`，多一个键就会被拒绝（`lib/document.js` 的 `readLogMetadata` 会报「日志文件的 meta_data 只能写 file_name 和 desc」）。

- `file_name` — 日期，也必须是日期；不是日期就不是日志。
- `desc` — **由插件按作用域写死，不能改**：全局那份是「用来记录和"他"之间的互动」，工作区那份是「用来记录项目相关操作」（`lib/log.js` 的 `LOG_DESCS`）。两边各写死一份，就永远不会出现两个地方说法不一致。

没有 `format`，也没有 `inject_ignore`：日志的每一部分都已经被渲染器定死了，没有可调的东西。

## 结构固定

一级标题是**当天日期**，和 `file_name` 相同。一级标题由插件维护，正文**开头**也不能是 `#`——`memory_edit` 的 `new_string` / `old_string` 以 `#` 开头会被当成改名标题、把当天的结构搞乱，所以直接拒绝。`#` 出现在正文中间或后面几行没问题，那是普通文字。

二级标题是「**时分 摘要**」，时分一律写成 `hh:mm`（冒号，不是连字符）。摘要写进标题而不是正文，是为了让一条记录一次调用就能写完：写摘要、写正文分两步做，中间会留下「有摘要没正文」的半空状态。摘要长度受 `logSummaryMaxChars` 限制，但**只在新写一条时校验**：上限调低以后，先前超长的旧条目照样能改正文和关键词，不用为了绕开检查去改它的标题。

`update_at` 和记忆文件一样，是本地墙上时间带时区偏移（`2026-10-27T12:35:10+08:00`）。

正文 `desc` 写细节。

关键词挂在**二级标题**上，一级标题没有。
