# 日志文件的格式

日志是**按天自动建**的：插件在 `start()` 和每次会话 `attach()` 时补建当天文件，零点过 5 秒再切到新一天（`lib/runtime.js` 的定时器，`unref()` 过）。不需要（也不应该）手工新建。所以这里记的是「落盘长什么样」，不是「复制这份开始写」。

`file_name` 就是日期，写成 `YYYY-MM-DD`。

## 整体形状

```yaml
meta_data:
  file_name: <yyyy-mm-dd>
  desc: <desc>

data:
  <yyyy-mm-dd>:
    <hh:mm> <summary>:
      update_at: <time>
      desc: <detail>
```

## `meta_data` 只能写两项

`file_name` 和 `desc`，多一个键就会被拒绝（`lib/document.js` 的 `readLogMeta` 会报「日志文件的 meta_data 只能写 file_name 和 desc」）。

- `file_name` — 日期，也必须是日期；不是日期就不是日志。
- `desc` — **由插件按作用域写死，不能改**：全局那份是「用来记录和"他"之间的互动」，工作区那份是「用来记录项目相关操作」（`lib/log.js` 的 `LOG_DESCS`）。两边各写死一份，就永远不会出现两个地方说法不一致。

没有 `format`，也没有 `inject_ignore`：日志的每一部分都已经被渲染器定死了，没有可调的东西。

## 结构固定

一级标题是**当天日期**，和 `file_name` 相同，**改不了**：改成别的日期就和文件名对不上，插件宁可拒绝。二级标题是「**时分 摘要**」，可以改名（换时分、换摘要或两者都换），正文和关键词跟着条目走，换时分后按新时间重新排序。

正文**开头**不能是 `#`。`#` 只出现在标题行：`old_string` / `new_string` 两边都写成标题行（`## 12:35 旧摘要` → `## 09:10 新摘要`）就是改名，否则以 `#` 开头的是想往正文里塞标题，直接拒绝。`#` 出现在正文中间或后面几行没问题，那是普通文字。

二级标题的时分一律写成 `hh:mm`（冒号，不是连字符）。摘要写进标题而不是正文，是为了让一条记录一次调用就能写完：写摘要、写正文分两步做，中间会留下「有摘要没正文」的半空状态。摘要长度受 `logSummaryMaxChars` 限制，但**只在新写一条、或改动摘要本身时校验**：上限调低以后，先前超长的旧条目照样能改正文、改关键词、只改时分，不用为了绕开检查去改它的标题。

`update_at` 和记忆文件一样，是本地墙上时间带时区偏移（`2026-10-27T12:35:10+08:00`）。

正文 `desc` 写细节。

关键词挂在**二级标题**上，一级标题没有。关键词为空时不写 `keyword:` 这一行（和记忆文件的标题节点一样）；`update_at` / `desc` 也是空则省略。
