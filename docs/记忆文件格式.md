# 记忆文件的格式

一个记忆文件就是一个 YAML 文件，落在某个作用域的 `.memory/` 目录下。**它是插件生成的，不是手工抄的模板**——新建走 `memory_manage`，之后由工具按下面的形状改写，所以这里看到的是「落盘长什么样」，不是「复制这份开始写」。

尖括号包着的 `<file_name>` 这类是待填的占位符，不是字面量。

## 整体形状

```yaml
meta_data:
  file_name: <file_name>
  desc: <desc>
  format: <format>
  scope: <scope>
  inject_ignore:
    - update_at
    - keyword

data:
  <t1>:
    keyword: []
    update_at: <time>
    desc: <desc>
    <t2>:
      keyword: []
      update_at: <time>
      desc: <desc>
```

只有 `meta_data` 和 `data` 两段，没有第三段。

## `meta_data`

- `file_name` — 文件的寻址名，也是 `memory_read` / `memory_edit` 的 `file_name` 参数。同一个名字可以在全局和工作区各有一份，靠 `scope` 区分。
- `desc` — 一句话说清这个文件记什么。会注入提示词，模型靠它决定该翻哪一本。
- `format` — 写这个文件的约定（比如「一条一件事」「只记和这个工作区有关的」）。**只进 `memory_edit` 的工具描述，不进注入**：读一次就够，每次重复没有意义。
- `scope` — `Global` 或 `Workspace`。
- `inject_ignore` — 注入提示词时跳过哪些部分。可选值：`t1` `t2` `t3` `t4`、`desc` `keyword` `update_at`，以及 `t2.desc` / `t3.keyword` 这类「层级.部分」组合。

  新建文件时不给这项，落盘就是 `update_at` 和 `keyword` 两条——这两个占的地方最多、变得最少。想注入回来就把对应那行删掉；写 `[]` 就是全都注入。

  它只影响**注入**，不影响读取：`memory_read` 永远返回全文，否则模型抄出来的 `old_string` 和编辑工具比对的内容就对不上了。

## `data`

`data` 下面是一棵标题树，每层节点是同一套字段：

- `keyword` — 关键词列表，用来让人和模型都能扫到。
- `update_at` — 这个标题最后一次改动的时间。
- `desc` — 这个标题的正文。
- 其余键都是下一级标题。

标题最多四层（`lib/model.js` 的 `LEVELS`）。`desc` / `keyword` / `update_at` 是保留字，不能拿来当标题名。

空字段不写：`desc` 是空串、`keyword` 是空列表时，落盘里就没有那一行。所以手写的文件和插件写出来的看起来一样。
